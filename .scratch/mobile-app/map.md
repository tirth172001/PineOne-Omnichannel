## Destination

A native Android app (React Native + Expo, TypeScript) in a new top-level `mobile/` folder in this same repo, that replicates every merchant-facing module built on the `pineone-omni/phase_2` branch as native screens, navigable under the 5-tab IA shown in the Figma app reference (Overview / Payments / Reports / Support / More). Reached when every phase_2 module has a corresponding native screen, built against the same mock-data model the web app already uses (no real backend exists on either side).

## Notes

- Domain: fintech merchant dashboard (PineOne Omnichannel), mirroring `pineone-omni/phase_2`.
- Tech: React Native + Expo + TypeScript, Expo Router for navigation. New top-level `mobile/` folder at repo root (sibling to `app/`, `components/`, `lib/`) — not a monorepo tooling setup, just colocated.
- **Component library: react-native-paper (Material 3)**, decided during ticket 03's revisions. PineOne's brand primary (`#365314`) seeds a full MD3 tonal palette via `@material/material-color-utilities` (Google's own algorithm — all ~30 color roles, not hand-picked), in `src/constants/paper-theme.ts`. All screens/components should use Paper's real components (`Appbar`, `Searchbar`, `Card`, `Banner`, `BottomNavigation.Bar`, `Text` with `variant`, etc.) themed via `useTheme()` from `react-native-paper`, not hand-rolled equivalents — the old custom `ThemedText`/`ThemedView`/`Colors` system was deleted once nothing depended on it. `BottomNavigation.Bar` also replaced the earlier hand-rolled, height-responsive tab bar — Material 3 owns tab bar sizing/interaction per its own spec now, so the custom responsive-height tiers were removed as redundant.
- Data: UI-only. The web app has no backend (`my-v0-project`, no fetch/API/DB deps found) — mock data lives in `lib/*-data.ts`. Mobile app should follow the same pattern; port/adapt mock data as needed rather than building real APIs.

Search moved out of the card into a floating action: `CollapsingDetailScreen` gained `floating` (rendered just above the footer) and `onScroll(offsetY, viewportHeight)`; the settlement page measures the transactions card and fades/raises a 12dp-radius FAB in while the section is on screen (and keeps it while a search is open); tapping it turns into a floating search bar with close. **No pagination — lazy loading**: 10 rows first, +10 (after a 500 ms simulated fetch with a spinner) whenever the list's end scrolls into view; "Showing N of M · scroll for more" / "All M transactions shown"; searching resets to 10. Other listings still paginate.
- **Storybook canvas decorator**: `.rnstorybook/preview.tsx` wraps every story in the theme's light background + 16dp padding, because Storybook's UI follows the OS color scheme and stories rendered dark-on-dark in OS dark mode.
- Platform: Android only for this effort (React Native chosen partly so iOS stays reachable later without a rewrite, but iOS work itself is out of scope now).
- **Expo Go constraint**: no Android emulator/dev-client tooling exists in this environment, so the user previews via Expo Go on their own phone. Any API requiring a native module not bundled in Expo Go (e.g. `expo-router/unstable-native-tabs`, discovered the hard way in ticket 03) will silently fail on-device while looking fine in web preview. Check Expo Go compatibility before adopting any new native-feeling API; prefer plain JS/`expo-router/ui` primitives by default.
