## Question

Ticket 09 established the field-level stagger pattern (`components/onboarding/stagger-fields.tsx`'s `<StaggerFields>`/`<StaggerField>`) and proved it on two representative screens: `business-basics` (onboarding, multi-field) and `/signup/password` (signup, single-field). The preview-panel half of the pattern (`<RevealField>`, the skeleton→value crossfade) was already applied everywhere it's relevant in `onboarding-preview.tsx`, since that's centralized in one file.

The remaining step files still use plain, un-staggered markup (no visible regression — they render fine, just without the new field choreography): `business-verification`, `store-verification`, `website-app-details`, `banking-details`, `business-owners`, `authorised-signatory`, `face-authentication` (the "confirm" phase, which shows `StepProgressBar`), `review-and-sign` (the pre-sign phase), and `/signup/email`, `/signup/otp`, `/signup/business-name`, `/signup/get-started`.

Resolve: mechanically apply `<StaggerFields>`/`<StaggerField>` to each remaining step's field groups, following the same shape used in `business-basics` and `/signup/password`. Also resolve the exception question ticket 09's map fog originally raised: do the full-width, no-split screens (`face-authentication`'s active capture phase, `review-and-sign`'s post-submission success phase) need any motion treatment at all, given they don't have "fields" in the same sense (camera capture, a static success message)? Likely no — same reasoning ticket 08 used to decide those phases don't get a back button either.

## Answer

Applied `<StaggerFields>`/`<StaggerField>` to all 12 remaining step files, following the exact shape from `business-basics`/`signup/password`: `StepProgressBar` (or its signup equivalent) stays a direct, non-animated child; each logical block — heading, form-group, button — gets its own `<StaggerField>` so blocks cascade in with a 60ms offset. For multi-branch screens (`business-verification`'s method/failed/verified states, `banking-details`'s upload/failed/confirm states), each conditional branch's blocks were wrapped independently — since the branches are separate JSX subtrees, swapping `step` state remounts fresh `StaggerField` children, which correctly replays the entrance choreography (a freshly-mounted child without its own `initial` prop inherits `StaggerFields`' `hidden`→`visible` transition from Framer Motion's variant propagation). `face-authentication`'s "confirm" phase had `StepProgressBar` pulled out of the heading's wrapper div to sit as a proper sibling, matching the convention everywhere else. `review-and-sign`'s pre-sign phase wraps each of the two cards (agreement, business details) as its own `StaggerField` so they cascade in as a pair.

Exception question resolved as predicted: **no** motion treatment for `face-authentication`'s active capture phase or `review-and-sign`'s post-submission success screen. Same reasoning ticket 08 used for back navigation — camera capture and a static success message aren't "fields," and per ticket 03 face-authentication's capture phase remains inside the split layout but still isn't a form to choreograph.

Found and fixed a real bug along the way (mechanical, needed for correctness): `banking-details`'s upload button was missing `w-full` — invisible before since it sat alone in a `flex-col` container that stretched it anyway, but became a visible width regression once wrapped in a `StaggerField` alongside sibling blocks. Added `w-full` back.

Spotted a pre-existing, unrelated issue while verifying in-browser: a Radix Accordion SSR hydration-id mismatch in `SignatoryBody`'s "Letter of Authorisation" accordion (ticket 02), reproducible on any route rendering that preview mode, predating this ticket. Flagged as a separate background task rather than fixed here.

Verified in-browser end-to-end: walked the full onboarding sequence (business-verification → business-basics → store-verification → website-app-details → banking-details → business-owners → authorised-signatory → face-authentication) and the full signup sequence (email → password → OTP → business-name → get-started), confirming every screen renders correctly with staggered entrance and no new console errors.
