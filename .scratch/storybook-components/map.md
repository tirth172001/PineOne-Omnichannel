# Map: Storybook for the shared component library

Label: wayfinder:map

## Destination

Storybook is installed and set up in this repo. Every component in `components/ui/`, `components/shared/`, `components/brand/` (and any other genuinely reusable, prop-driven component uncovered along the way) has a story that imports its real source file and documents all its props/variants — so the story is never a copy, and editing the source updates both the app and Storybook. In parallel, the codebase is audited for duplicate/near-duplicate implementations of the same UI pattern living in feature folders instead of using the shared ones; genuine duplicates get consolidated into the canonical shared component so future edits propagate everywhere that pattern is used.

Reaching the end of this map means: the tooling and authoring decisions below are settled, the duplicate audit is complete and its consolidation tickets are resolved, and every in-scope component has a story — built straight through (see Notes), not handed off to a separate build effort.

## Notes

- Domain: Pine One merchant dashboard (Next.js 16, React 19, Tailwind v4, `tailwindcss-animate`, `next-themes`). `components/ui/` is a shadcn-style primitives folder (~60 files); `components/shared/` holds cross-feature composites (~8 files, e.g. `status-pill.tsx`, `summary-card-group.tsx`, `transaction-style-table.tsx`); `components/brand/` is small (`logo-mark.tsx`).
- **Scope boundary, locked while naming the destination (grilled 2026-08-19):**
  - In scope: `components/ui/`, `components/shared/`, `components/brand/`, plus any component the duplicate audit (ticket 03) surfaces as a de-facto reusable pattern worth promoting into `shared/`.
  - Out of scope: page/feature "content shell" components (e.g. `components/transactions/transactions-content.tsx`, `components/settlements/v3-settlements-content.tsx`, everything under `components/dashboard/*`) — these own state, fetch/hardcode their own data, and assemble one specific screen rather than being instantiated with varying props. See Out of scope section.
  - Stories must import the real component source, never a copy — this is how prop/behavior changes propagate to Storybook for free.
- **Decisions-then-build-straight-through**: this map's tickets settle tooling/convention questions and audit for duplicates; once a ticket resolves, the resulting work (install, write stories, consolidate a specific duplicate) happens directly, same session or a follow-on session against this map — no separate hand-off effort.
- **Execution mode**: unlike a decisions-only map, `task` tickets here (e.g. installing Storybook, writing a batch of stories, consolidating an agreed duplicate) do the work directly rather than just describing it. Record what was actually built in the ticket's `## Answer`.
- Hosting: local only (`pnpm storybook` / whatever script setup lands on) — no deployment target (Chromatic/Vercel/Pages) decided yet or needed. See Not yet specified.
- Documentation-only: no interaction tests, visual regression, or Chromatic wiring — see Out of scope.
- Use `/mattpocock-skills:grilling` for `grilling`-type tickets, `/mattpocock-skills:research` for `research`-type tickets.
- When resolving a ticket: append the answer under the ticket's `## Answer` heading, set `Status: resolved`, and append a context pointer to this map's Decisions so far.

## Decisions so far

- [Z-index foundation](issues/13-zindex-foundation.md) — documented the real stacking layers in use: z-0/1 decorative, z-10 local elevation (largest tier, 15 files), z-20 nested local, z-40 page chrome, z-50 as Radix's own baked-in global-overlay default, plus three independent arbitrary escapes above it (`z-[70]` unexplained, `z-[100]` toast-over-dialogs — deliberate, `z-[220]` the highest value by a wide margin — unexplained). Added `components/foundations/zindex.stories.tsx` and a `ZIndexTier` primitive; whether to rationalize the arbitrary values into a named scale is left open in Not yet specified.
- [Motion foundation](issues/14-motion-foundation.md) — documented real, already-consistent motion language that just isn't centralized: every Framer Motion panel transition uses the identical `cubic-bezier(0.22, 1, 0.36, 1)` easing (duplicated as a local literal per file, not a shared constant) at 0.2s–0.28s; Tailwind `duration-100` is the de facto standard for Radix overlay open/close (7 primitives), `duration-200` for layout expand/collapse; four one-off values (`150`/`250`/`300`/raw-CSS-`180ms`) don't match either tier. Added `components/foundations/motion.stories.tsx` with a live hoverable `MotionSample` primitive, verified interactive in Storybook.
- [Container width foundation](issues/15-container-width-foundation.md) — grouped 94 `max-w-*` call sites by layout context: full-page shells have no shared value except a 1440px cluster (4 files); article/form widths reuse Tailwind's named scale well but 560px/520px sit unexplained in the `lg`/`xl` gap; dialog/sheet content is the messiest — shadcn's own `sm`(384px)/`md`(448px) defaults coexist with a parallel set of near-duplicate arbitrary pixel values that never reuse the token; chat bubbles use a coherent `92%` percentage cap (8 call sites); `full`/`max`/`calc(...)` escapes are legitimate, not inconsistency. Added `components/foundations/containers.stories.tsx` with a `ContainerWidthBar` primitive, verified live.

- [Storybook setup approach](issues/01-storybook-setup-approach.md) — `@storybook/nextjs-vite` (Storybook 10), Tailwind v4 needs only `import '../app/globals.css'` in preview (Vite auto-runs the existing PostCSS pipeline), `@storybook/addon-themes`'s `withThemeByClassName` for light/dark, `@/*` aliases resolve automatically, addons needed: `addon-docs`/`addon-a11y`/`addon-themes` (controls/actions/viewport now core). Full citations in [research/01-storybook-setup-approach.md](research/01-storybook-setup-approach.md).
- [Duplicate component audit](issues/03-duplicate-component-audit.md) — three independent empty-state implementations found (`PanelEmpty`, an unused `Empty` primitive, and two ad-hoc `emptyText` strings) → spun off as [Canonical empty-state component](issues/05-canonical-empty-state-component.md). Two competing table components (`data-table.tsx` vs `transaction-style-table.tsx`) flagged but not yet ticketed — needs investigation first (see Not yet specified). `StatusPill`/`Avatar` adoption checked clean, no widespread duplication found.
- [Story authoring conventions](issues/02-story-authoring-conventions.md) — co-located `*.stories.tsx`, sidebar mirrors folder structure (`UI/Button`, `Shared/StatusPill`), autodocs-first (hand-annotate only when types are ambiguous), one `Default` story with full Controls per component (named extra stories only for states Controls can't reach), one story per composite (not per sub-part), inline mock data for `shared/*` composites. Full template in the ticket's `## Answer`.
- [Install and scaffold Storybook](issues/04-install-and-scaffold-storybook.md) — `@storybook/nextjs-vite` + `addon-docs`/`addon-a11y`/`addon-themes` installed and verified live (port 6006); `.storybook/main.ts` and `preview.ts` created; `components/ui/button.stories.tsx` is the first real story, proving the whole pipeline (theming, Tailwind, autodocs, controls). Deviation: switched to `typescript.reactDocgen: 'react-docgen-typescript'` (ticket 1's documented fallback) because the default docgen didn't extract `cva()` variant/size unions correctly — now fixed. Minor known gap: `variant`/`size` Controls render as text boxes not select dropdowns (docs are accurate; only live-editing convenience affected) — left as a per-component call for later stories.
- [Form & input primitives](issues/06-stories-form-inputs.md) — 16 stories written and verified live. `input-otp.tsx`'s discriminated-union prop type broke Storybook's type inference; fixed with a local `{ maxLength: number }` typing cast for the story only (real component/props unaffected, autodocs still reads the real source). `Form`'s story wires real `react-hook-form` + `zod` validation, not just bare props.
- [Overlays & navigation](issues/07-stories-overlays-navigation.md) — 18 stories written and verified live, all using `defaultOpen: true` for click-triggered overlays except `ContextMenu` (positioned by the real right-click event, so shown via its trigger with working real right-click interaction instead).
- [Data display](issues/08-stories-data-display.md) — 14 stories written and verified live at mobile/desktop widths. `Chart`'s bars looked broken on first paint (transient `ResizeObserver` timing in the iframe, not a real bug — settled correctly). Surfaced capability evidence for the `data-table` vs `transaction-style-table` question, still left in Not yet specified.
- [Feedback & layout](issues/09-stories-feedback-layout.md) — 9 of 10 stories written; `toaster.tsx` skipped (real "Invalid hook call" bug, legacy/unused Radix toast stack — flagged separately, not fixed here). `resizable.tsx` was actually fixed (wrong `react-resizable-panels` API, zero consumers so zero-risk) — `tsc` baseline now 29, was 34.
- [Shared & brand](issues/10-stories-shared-and-brand.md) — all 9 files storied; two multi-component files (`listing-page-primitives.tsx`, `activity-timeline-sidepanel.tsx`) needed `Meta.component` omitted since CSF3 only allows one per file. `bulk-operation-sheet.tsx` reproduces a known pre-existing, widespread `a11yTitle` prop bug — storied as-is, not fixed (unlike ticket 9's contained `resizable.tsx` fix).
- [DataTable vs TransactionStyleTable convergence](issues/11-datatable-vs-transactionstyletable-convergence.md) — converged onto `DataTable`. Every call site's bespoke search bar was reimplementing what `DataTable` gives for free — clear consolidation win. `TransactionStyleTable` deleted; one call site (pending-users approval queue) deliberately kept its external search because "select all" depends on knowing the currently-filtered rows, which `DataTable`'s internal search state would have hidden from the parent.
- [Icon library convergence](issues/12-icon-library-convergence.md) — converged onto `@phosphor-icons/react`, dropping `lucide-react` and the unused `@hugeicons/*` packages entirely; standardized every call site on the `Icon`-suffixed import name. 91 files migrated off lucide (89 under `components/`/`app/` plus 2 under `lib/` the original ticket scope missed), 21 files normalized onto the suffix convention, ~152 icon names mapped with a documented non-exact list for the ~16 with no 1:1 Phosphor match. `tsc` stayed at the 29-error baseline.
