## Question

Write stories for the feedback/layout/misc components in `components/ui/`, following [Story authoring conventions](02-story-authoring-conventions.md):

`alert.tsx`, `toast.tsx`, `toaster.tsx`, `sonner.tsx`, `skeleton.tsx`, `spinner.tsx`, `resizable.tsx`, `scroll-area.tsx`, `panels.tsx`, `empty.tsx`.

`panels.tsx` exports a compound family (`Panel`, `PanelHeader`, `PanelTitle`, `PanelActions`, `PanelBody`, `PageHeader`, `PanelHeading`, `PanelSubheading`, `PanelCopy`, `PanelSection`) — one story showing a realistic assembled panel, per convention #5. Note: `PanelEmpty` no longer exists — [Canonical empty-state component](05-canonical-empty-state-component.md) resolved in favor of `empty.tsx`'s `Empty`/`EmptyHeader`/`EmptyMedia`/`EmptyTitle`/`EmptyDescription`/`EmptyContent`, which is now a real in-scope component needing its own story too (one story per assembled example, e.g. icon + title + description, plus a variant showing `EmptyContent` with an action button since that's its actual differentiator).

## Answer

Stories written for: `alert`, `toast`, `sonner` (`SonnerToaster`), `skeleton`, `spinner`, `resizable`, `scroll-area`, `panels` (two stories: `PanelLayout` and `PageHeaderExample`), `empty` (two stories: `Default` and `WithAction`, the latter demonstrating `EmptyContent`'s action-button slot — its actual differentiator per ticket 5).

**`toaster.tsx` — no story written; found a real bug.** `Toaster` (built on `hooks/use-toast.ts` + the standalone `@radix-ui/react-toast@1.2.4` package) throws "Invalid hook call" / "Cannot read properties of null (reading 'useState')" when rendered under Storybook's Vite bundler — reproduced consistently across fresh page loads, not a transient issue. This pairs with an earlier finding (nothing in the live app imports `Toaster` from `toaster.tsx` — `sonner.tsx`'s `Toaster` is what's actually wired into `app/layout.tsx`) and the fact that `@radix-ui/react-toast` is a standalone legacy package, distinct from the unified `radix-ui` package every other component in this codebase uses. Likely a React-19-incompatible legacy dependency that nobody noticed because it's never actually rendered. The `Toast` primitive story (which doesn't depend on the broken hook) still documents the composed visual pattern correctly. Flagging this pair (`toast.tsx`/`toaster.tsx`/`hooks/use-toast.ts`) for a separate decide-and-clean-up pass — out of scope to fix here since it's not just an unused-file deletion, it's an actual runtime incompatibility.

**`resizable.tsx` — found and fixed a real, unrelated bug** (in scope to fix since it directly blocked writing this story): the component was written against an old `react-resizable-panels` API (`ResizablePrimitive.Group`/`.Separator`), but the installed `v2.1.9` only exports `Panel`/`PanelGroup`/`PanelResizeHandle` — confirmed via `node -e "require('react-resizable-panels')"`. This exactly matched 4 of the pre-existing 34 baseline TS errors (`Property 'Group' does not exist`, etc.). Fixed `components/ui/resizable.tsx`: renamed to the real v2 exports, and updated the handle's orientation-dependent styling from the old `aria-[orientation=...]` selectors (which no longer apply) to the real `data-[panel-group-direction=...]` attribute the new API sets — verified the horizontal/vertical logic wasn't just search-replaced blindly (the old ARIA "orientation" was the separator's own axis, inverted from the group's `direction`; the new `data-panel-group-direction` attribute is the group's actual direction, so the conditional was flipped accordingly, not copied verbatim). `resizable.tsx` has zero consumers in the app today, so this was zero-blast-radius to fix. TS baseline dropped from 34 → 29 errors as a result. Verified live: panels render, drag-to-resize works.

**Verified live in the browser**: `SonnerToaster` (the real one) shows a working success toast. `Empty`'s `WithAction` story shows the action button correctly. `Panels`' `PanelLayout` renders two side-by-side panels with headers/badges. `Resizable` renders and drag-resizes correctly post-fix. No other console/server errors. `tsc --noEmit` is now at **29** errors (down from the 34-error baseline, due to the `resizable.tsx` fix) — no new errors introduced by any story file.
